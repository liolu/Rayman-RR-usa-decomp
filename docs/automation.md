# Automation

Everything that does not need a human is scripted. A human (or an assistant) only writes C code; the tools build,
check, suggest drafts, brute-force near matches and publish.

| Tool | What it automates |
|---|---|
| `tools/moulinette.py` | The whole pipeline in one command (see below) |
| `tools/match.py` | Progress (`status`), worklist, single-function check, strict `verify`, README progress table |
| `tools/draft.py` | C drafts generated by [m2c](https://github.com/matt-kempster/m2c) from the disassembly |
| `tools/permute.py` | [decomp-permuter](https://github.com/simonlindholm/decomp-permuter): random rewrites of an almost-matching function until it matches |
| `tools/probe_compiler.py` | One function against every compiler version / flag set |
| objdiff (GUI) | Rebuilds and re-diffs automatically every time a source file is saved |

## The moulinette

```shell
python tools/moulinette.py                          # sync, build, drafts, verify, commit and push to main
python tools/moulinette.py --no-push                # commit locally only
python tools/moulinette.py --no-commit              # verify only
python tools/moulinette.py --permute func_0200cbdc --minutes 30
```

Steps:
1. `git pull --ff-only`
2. `configure.py` (first time) and `ninja`: extract, split, link and rebuild the ROM
3. `ninja dis`, then m2c drafts for every unmatched function of the delinked files → `build/drafts/<function>.c`
4. Optional permuter run on one function → `build/permuter/<function>/output-<score>-*/source.c`
5. `match.py verify`: byte-identical ROM, every `complete` file at 100%, ASCII-only sources
6. If the verification passed and something changed: README progress table, pre-commit hooks (then verify again if
   they reformatted code), commit listing the newly matched functions, `git push origin HEAD:main`

Nothing is committed or pushed when a check fails. Because publishing goes straight to `main`, the verification is
the only safety net: never bypass it.

## Daily loop (human part)

1. Run the moulinette once: it refreshes drafts for the functions left to do.
2. Open objdiff on the project, pick a function, start from `build/drafts/<function>.c`.
3. Edit the C file in `src/`; objdiff rebuilds on save. Iterate until 100%.
4. Stuck at a few instructions? `python tools/moulinette.py --permute <function> --minutes 30` and come back later.
5. Run the moulinette again: it verifies and publishes.

## Installing the optional tools

m2c (GPL-3.0) and decomp-permuter are not shipped with this repository.

```shell
git clone https://github.com/matt-kempster/m2c
git clone https://github.com/simonlindholm/decomp-permuter
python -m pip install graphviz toml Levenshtein psutil
```

Point `M2C_PATH` and `PERMUTER_PATH` to the clones (defaults: `tools/m2c` and `tools/decomp-permuter`).
The permuter also needs `bash`, `gcc`, `arm-none-eabi-as` and `arm-none-eabi-objdump` in `PATH`.

> [!WARNING]
> On Windows, `bash` must be Git Bash, not `C:\Windows\System32\bash.exe` (WSL): put Git's `bin` directory first
> in `PATH`.

## Notes
- m2c output is a draft, not a solution: it ignores the original types and often uses temporaries
  (`temp_r2`). Clean it up following [engine.md](engine.md).
- The permuter score is a distance: 0 means a match. Copy the winning `source.c` back into the real file and check
  with objdiff; the permuter can produce unnatural code, so tidy it up while keeping the match.
- `permute.py` kills its worker processes with `psutil`, because `taskkill /T` relies on WMI, which is broken on
  some Windows installations.
